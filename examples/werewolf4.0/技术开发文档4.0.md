# 🐺 Project: DeepWerewolf (Concordia + Neo4j + Dify) 技术开发文档

**版本**: v3.0 (Graph-Based Perspective Architecture)
**核心架构**:
*   **Body**: Concordia (Python) - 状态机与私有状态管理
*   **Logic**: Neo4j (Graph DB) - 全局事实与可见性过滤
*   **Brain**: Dify (LLM Workflow) - 认知决策与自然语言生成

---

## 1. 项目概述 (Project Overview)

本项目旨在构建一个支持 6-12 人局的高拟真狼人杀 AI 模拟系统。

### 核心设计哲学
1.  **单一事实，多重视角 (Single Truth, Multiple Views)**: 使用单一 Neo4j 图数据库存储全量游戏事实，通过动态过滤机制为不同角色生成主观逻辑图谱。
2.  **身心分离**:
    *   **Concordia** 维护物理状态、私有猜想（怀疑度）和短期记忆。
    *   **Dify** 负责基于视角的逻辑推理、伪装策略生成和自然语言表达。
3.  **图驱动博弈**: 利用图数据库解决“利益链分析”、“团队识别”和“逻辑闭环”等高阶问题。

## 3. 数据结构设计 (Data Structures)

### 3.1 Neo4j 图谱模型 (Global Truth)

**核心设计**: 所有关系必须包含 `visibility` 属性，用于权限控制。

**节点 (Nodes)**
*   `:Player {id: "P1", role_real: "WEREWOLF"}` (真实身份仅上帝可见)
*   `:Event {type: "SPEECH", round: 1}`

**关系 (Relationships) - 动作与逻辑**
*   **公开行为 (Public)**:
    *   `[:CLAIM {role: "SEER", visibility: "PUBLIC"}]` (跳身份)
    *   `[:CHECK {result: "GOLD", visibility: "PUBLIC"}]` (报验人 - 注意这是声称的动作)
    *   `[:VOTE_FOR {round: 1, visibility: "PUBLIC"}]` (投票)
    *   `[:ATTACK {reason: "...", visibility: "PUBLIC"}]` (踩)
*   **私密行为 (Private)**:
    *   `[:NIGHT_KILL {target: "P5", visibility: "WEREWOLF_TEAM"}]` (狼刀)
    *   `[:NIGHT_CHECK {result: "WEREWOLF", visibility: "SEER_ONLY"}]` (真预言家验人)
    *   `[:NIGHT_SAVE {target: "P5", visibility: "WITCH_ONLY"}]` (女巫救人)

### 3.2 Concordia 私有状态 (Private State)

存储在 Python 内存/数据库中，不存入 Neo4j（避免图谱爆炸）。

```python
class PlayerState:
    def __init__(self):
        # 怀疑矩阵：纯主观猜想
        self.suspicion_matrix = {"P3": 80, "P6": 10}
        # 待处理问题
        self.pending_questions = []
        # 当前战术目标 (由夜间策略生成)
        self.objective = "悍跳预言家"
```

### 3.3 Dify 交互载体 (Context Payload)

每次调用 Dify 时，GM 组装以下 JSON：

```json
{
  "static_info": { "role": "村民", "player_id": "P2", "teammates": [],},

  // 来自 Neo4j (经过视角过滤)
  "objective_facts": [
    "P1 跳预言家，给 P3 发金水 (Public)",
    "P4 投票给 P1 (Public)"
  ],

  // 来自 Concordia (私有状态)
  "subjective_state": {
    "suspicion": { "P1": 90, "reason": "发言太假" },
    "objective": "站边真预言家 P6，攻击 P1"
  },

  // 逻辑推导 (由 Python 根据图谱预计算)
  "logic_hints": [
    "如果你怀疑 P1 是狼，那么 P1 的金水 P3 大概率也是狼或被拉票的好人。",
    "P4 的票型通过逻辑与 P1 绑定。"
  ]
}
```

## 4. 关键模块详细设计

### 4.1 逻辑层：视角过滤器 (Perspective Filter)

这是本架构的核心组件，负责生成“主观图谱”。

**Python 实现逻辑**:

```python
def get_player_view(player_id, player_role, neo4j_driver):
    # 定义可见性集合
    visible_tags = ["PUBLIC"]
    if player_role == "WEREWOLF":
        visible_tags.append("WEREWOLF_TEAM")
    elif player_role == "SEER":
        visible_tags.append("SEER_ONLY")
    # ... 其他角色逻辑

    # Cypher 查询模板
    query = """
    MATCH (actor:Player)-[r]->(target)
    WHERE r.visibility IN $tags
    RETURN actor, r, target
    """
    return neo4j_driver.run(query, tags=visible_tags)
```

### 4.2 认知层：Dify Workflow 设计

**Workflow ID**: `DeepWerewolf_Brain_v3`

**节点 1：夜间策略生成 (Night Strategy)**
*   **Trigger**: 首夜或每晚入夜。
*   **Input**: 狼人团队视图 (能看到 `NIGHT_KILL` 历史)。
*   **Task**: "基于今晚没死的预言家名单，决定下一刀，并分配悍跳/倒钩任务。"

**节点 2：白天发言生成 (Day Speech)**
*   **Input**: `objective_facts` (事实), `subjective_state` (猜想)。
*   **Step 1 (Logic Check)**: "结合事实与猜想。例如：事实是 P1 给 P3 金水，猜想是 P1 为狼。推导出 P3 的身份可能性。"
*   **Step 2 (Consistency)**: "检查你的 `objective`。如果你决定倒钩，不要攻击你的狼队友，除非是为了做高身份。"
*   **Step 3 (Generation)**: "生成发言，必须回应 `pending_questions`。"

### 4.3 引擎层：事件解析器 (Event Parser)

负责将自然语言转化为图谱关系。

*   **输入**: P1 发言 "我觉得 P3 像狼，P4 可能是好人"。
*   **处理**: 调用 NLP 模型提取三元组。
*   **输出写入 Neo4j**:
    *   `MATCH (p1:Player {id: "P1"}), (p3:Player {id: "P3"}) CREATE (p1)-[:ATTACK {reason: "像狼", visibility: "PUBLIC"}]->(p3)`
    *   `MATCH (p1:Player {id: "P1"}), (p4:Player {id: "P4"}) CREATE (p1)-[:DEFEND {reason: "像好人", visibility: "PUBLIC"}]->(p4)`

## 5. 核心交互流程 (The Loop)

### 场景：真预言家 P1 查杀 P2 (狼人)

1.  **夜间 (Concordia)**:
    *   P1 发动技能查验 P2。
    *   **Write Neo4j**: `(P1)-[:NIGHT_CHECK {result: "WEREWOLF", visibility: "SEER_ONLY"}]->(P2)`。

2.  **白天发言 (Dify)**:
    *   轮到 P1。
    *   **Filter**: P1 能看到 `SEER_ONLY` 的关系。
    *   **Dify Input**: "已知事实：你昨晚查验 P2 是狼人。"
    *   **Dify Output**: "我是预言家，昨晚验了 P2，查杀！全票出 P2！"

3.  **事件广播 (Concordia)**:
    *   解析 P1 发言。
    *   **Write Neo4j**: `(P1)-[:CLAIM {role: "SEER", visibility: "PUBLIC"}]->(:Role)`, `(P1)-[:CHECK {result: "KILL", visibility: "PUBLIC"}]->(P2)`。

4.  **平民 P3 视角 (Dify)**:
    *   轮到 P3。
    *   **Filter**: P3 只能看到 `PUBLIC` 关系。
    *   **Dify Input**: "事实：P1 跳预言家查杀 P2。P2 还没发言。"
    *   **Dify Thinking**: "暂时站边 P1，听 P2 怎么辩解。"

## 6. 开发实施计划 (Implementation Plan)

### Phase 1: 图谱构建 (Graph Foundation)
*   **Neo4j**: 部署并设计 Schema，确保 `visibility` 属性覆盖所有关系。
*   **Adapter**: 编写 `Neo4jAdapter.py`，实现基于 `visible_tags` 的查询接口。

### Phase 2: 逻辑映射 (Logic Mapping)
*   **Parser**: 开发 NLP 模块，将 Dify 的 JSON 输出（如 `action_intent`）转化为 Neo4j 的 Cypher 写入语句。
*   **Inference**: 编写 Python 脚本，根据图谱结构生成自然语言的 `logic_hints` (逻辑提示)。

### Phase 3: 认知闭环 (Cognitive Loop)
*   **Concordia**: 集成 `PlayerState` (私有猜想) 与 `Neo4j` (客观事实)。
*   **Dify**: 优化 Prompt，教会 AI 如何处理“事实”与“猜想”的冲突（即逻辑博弈）。

### Phase 4: 高级博弈 (Advanced Gameplay)
*   **Strategy**: 实现狼人夜间基于图谱（如：谁是预言家面最大）的刀人策略。
*   **Tuning**: 调整不同角色的逻辑权重（如暴民更容易信且轻易怀疑，高玩更看重票型）。

## 7. 总结

本架构通过 **Neo4j** 实现了上帝视角的统一存储，通过 **Visibility Filter** 实现了千人千面的主观逻辑，通过 **Dify** 实现了拟人化的博弈表达。这是解决狼人杀 AI “逻辑不严密”、“视角混乱”问题的终极方案。
