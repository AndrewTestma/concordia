# 🐺 Project: DeepWerewolf (Concordia + Neo4j + Dify) 技术开发文档

**版本**: v2.0 (Neuro-Symbolic Enhanced)
**核心架构**:
*   **Body (Physics & Memory)**: Concordia (Python)
*   **Logic (Reasoning Engine)**: Neo4j (Graph Database)
*   **Brain (Cognition & Speech)**: Dify (LLM Workflow)

---

## 1. 项目概述 (Project Overview)

本项目旨在构建一个**高拟真、强逻辑、具备长线博弈能力**的狼人杀 AI 模拟系统（支持 6-12 人局）。

### 核心差异化优势
1.  **图谱驱动逻辑 (Graph-Driven Logic)**: 引入 **Neo4j** 替代传统的规则脚本，利用图算法解决“利益链分析”、“团队识别”和“逻辑闭环检测”等高阶博弈难题。
2.  **身心分离架构**:
    *   **Concordia** 负责维护“客观物理世界”和“主观记忆切片”。
    *   **Dify** 负责“主管能动性”，生成符合人设的伪装、煽动和推理发言。
3.  **策略前置 (Pre-Strategy)**: 引入“夜间战术会议”机制，确保狼队有组织、有纪律，好人有心路历程。

## 3. 核心数据结构 (Data Structures)

### 3.1 Neo4j 图谱模型 (Graph Schema)

**节点 (Nodes)**
*   `:Player {id: "P1", role: "UNKNOWN"}` (基础玩家节点)
*   `:Event {type: "SPEECH", round: 1}` (事件节点，用于回溯)

**关系 (Relationships) - 动态逻辑链**
*   `[:CHECK {result: "KILL"|"GOLD"}]`: 预言家查验（强逻辑边）
*   `[:VOTE_FOR]`: 投票行为（站边信号）
*   `[:ATTACK {reason: "..."}]`: 发言攻击（敌对信号）
*   `[:DEFEND {reason: "..."}]`: 发言保护（盟友信号/拉票信号）
*   `[:CLAIM {role: "SEER"}]`: 跳身份
*   `[:SIDE_WITH]`: 明确站边某预言家

### 3.2 Dify 交互载体 (Context Payload)

每次调用 Dify 时，GM 会组装以下 JSON：

```json
{
  "static_info": {
    "role": "WEREWOLF",
    "teammates": ["P2", "P3"],
    "player_id": "P1"
  },
  "dynamic_state": {
    "phase": "DAY_2_SPEECH",
    "alive_status": "ALIVE",
    "known_facts": ["昨晚刀 P5 成功", "P3 是悍跳队友"],
    "current_objective": "倒钩，假装好人，踩 P3 (队友)"
  },
  "logic_analysis": {
    "enemies": ["P6 (站边真预言家)", "P8 (攻击过我)"],
    "potential_allies": ["P2 (队友)", "P9 (逻辑混乱的好人)"],
    "contradictions": ["警告：你若站边真预言家，必须攻击 P3，否则逻辑不闭环"]
  },
  "social_context": {
    "pending_questions": ["P4 问：你为什么弃票？"],
    "suspicion_matrix": { "P6": 80, "P8": 60 }
  },
  "memory_excerpts": "..." // 基于仇恨值 Top-K 检索出的关键对话
}
```

## 4. 关键模块详细设计

### 4.1 逻辑层：Neo4j 推理引擎 (Inference Engine)

我们需要编写一组 **Cypher 模板**，用于在不同场景下提取逻辑。

**场景 A：寻找“倒钩狼” (Find Deep Water Wolf)**
*   *Query*: 谁声称站边真预言家，但投票行为却在帮悍跳狼？
*   *Cypher*:
    ```cypher
    MATCH (p:Player)-[:SIDE_WITH]->(real_seer)
    WHERE (p)-[:VOTE_FOR]->(fake_seer_target)
    RETURN p.id AS suspect
    ```

**场景 B：利益链分析 (Interest Chain)**
*   *Query*: 悍跳狼 P1 给 P2 发金水，P2 的身份定义？
*   *Cypher*:
    ```cypher
    MATCH (p1:Player {id: "P1"})-[:CHECK {result: "GOLD"}]->(p2:Player)
    RETURN p2.id, "疑似狼队友或拉票对象" AS logic
    ```

### 4.2 认知层：Dify Workflow 设计

**Workflow ID**: `Werewolf_Brain_v2`

**节点 1：夜间策略生成 (Night Strategy)**
*   **Trigger**: 首夜或每晚入夜。
*   **Prompt**: "作为狼人团队，基于当前 Neo4j 分析出的【威胁名单】（如没死的预言家），决定今晚刀谁，并分配战术（悍跳/倒钩）。"

**节点 2：白天发言生成 (Day Speech)**
*   **Input**: `logic_analysis` (来自 Neo4j), `memory_excerpts` (来自 Concordia).
*   **Step 1 (CoT)**: "分析 `logic_analysis` 中的逻辑链。如果你是倒钩狼，思考如何用逻辑去踩你的队友 P3，从而做高自己身份。"
*   **Step 2 (Speaker)**: "生成发言。必须回应 `pending_questions`。语气要符合你的伪装身份。"

### 4.3 引擎层：Concordia 状态机

**Listener Agent (监听器)**
*   当 P1 发言结束，GM 解析发言（可调用简单 LLM 提取结构化信息）：
    *   "我是预言家，查杀 P2" -> 写入 Neo4j: `(P1)-[:CLAIM]->(SEER)`, `(P1)-[:CHECK {result: "KILL"}]->(P2)`。
    *   "我觉得 P3 像狼" -> 写入 Neo4j: `(P1)-[:ATTACK]->(P3)`。

## 5. 核心交互流程 (The Loop)

### 阶段 I: 开局冷启动 (Cold Start)
1.  **GM**: 分配身份。
2.  **Logic**: 注入初始逻辑（平民=无信息，预言家=有查验）。
3.  **Strategy**: 触发“夜间战术会议”。
    *   狼队 Dify: "P1 悍跳，P2 倒钩"。
    *   GM: 将策略写入 P1, P2 的 `objective`。

### 阶段 II: 白天博弈 (Day Cycle)
1.  **发言 (Speech)**:
    *   GM 轮到 P1。
    *   **Neo4j**: 查询 P1 的视角图谱（谁是敌，谁是友）。
    *   **Concordia**: 检索 P1 仇恨值最高的 P6 的历史发言。
    *   **Dify**: 生成攻击 P6 的发言。
2.  **解析 (Parse)**:
    *   GM 捕获 P1 发言。
    *   **Write**: 更新 Neo4j 图谱（P1 ATTACK P6）。
    *   **Broadcast**: 通知所有玩家更新 `suspicion_matrix`。

### 阶段 III: 投票 (Voting)
1.  **Dify**: 询问每个玩家 "Vote Target"。
2.  **Neo4j**: 记录 `[:VOTE_FOR]` 关系（这是最铁的逻辑证据）。

## 6. 开发实施计划 (Implementation Plan)

### Phase 1: 基础设施 (Infrastructure)
*   **Neo4j**: 部署 Neo4j 数据库，设计初始 Schema。
*   **Concordia**: 搭建 Python 游戏循环，实现 `Neo4jAdapter` 类。
*   **Dify**: 创建基础 Workflow，打通 API。

### Phase 2: 逻辑闭环 (Logic Loop)
*   **Parser**: 实现“发言 -> 图谱”的解析器（这是难点，需要微调一个小模型专门做提取）。
*   **Inference**: 编写核心 Cypher 查询模板（查杀链、票型分析）。

### Phase 3: 策略与记忆 (Strategy & Memory)
*   **Strategy**: 实现“夜间战术会议”和 `objective` 动态更新。
*   **Memory**: 实现基于 `suspicion_matrix` 的 Top-K 检索。

### Phase 4: 调优与扩展 (Fine-tuning)
*   **Knowledge**: 导入 Godlie 数据集到 Dify。
*   **Scale**: 扩展到 12 人局（增加女巫、猎人技能逻辑）。

## 7. 风险评估

1.  **解析准确率**: 将自然语言发言转化为 Neo4j 关系（如“P1 踩 P2”）可能不准。
    *   *对策*: 在 Dify 输出 JSON 时，强制要求输出 `structure_actions` 字段，让发送者自己标记“我在攻击谁”，而不是靠接收者去猜。
2.  **图谱爆炸**: 12 人局多轮次后，关系极其复杂。
    *   *对策*: 只查询最近 3 轮的强逻辑关系（查杀、投票），忽略早期的弱关系（口头怀疑）。
