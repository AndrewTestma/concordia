### **3人局狼人杀（1狼人、1预言家、1村民）技术研发文档**

本项目基于 **Google DeepMind 的 Concordia 框架**（最新版本 v2.1.0，截至 2025 年 12 月仍活跃维护）实现一个最小可玩的 AI 狼人杀模拟：**3 人局**（角色配置：1 狼人 Werewolf、1 预言家 Seer、1 村民 Villager）。
这个配置是最简闭环，能完整覆盖**信息不对称**、**夜晚私有行动**、**白天公开讨论**、**投票处决** 和 **胜负判定**，适合快速调试和迭代。

设计原则：

- **硬规则引擎 + 软社会模拟**：用 Python 状态机严格控制游戏流程和规则（防止 LLM 幻觉），用 Concordia 的 Agent 系统负责记忆、思考和对话（发挥 LLM 的角色扮演优势）。
- **信息隔离**：夜晚行动完全私有，白天讨论公开。
- **多模型接入**：通过 **LiteLLM** 统一路由不同 LLM，实现“不同角色不同智商/风格”。
- **最小化实现复杂度**：先跑通核心循环，再扩展到 6 人局。

#### **一、整体系统架构**

系统分为 4 层：

1. **游戏控制层（Game Master / Engine）**
    核心状态机，负责流程推进、规则执行、胜负判定。
2. **Concordia Agent 层（Social Simulation Layer）**
    每个玩家是一个 Concordia Agent，负责记忆存储、内心思考和生成发言/行动。
3. **自定义组件层（Components）**
    扩展 Concordia 的 Component 系统，注入狼人杀特定逻辑（如双重思维、私有行动）。
4. **模型路由层（LLM Gateway）**
    使用 LiteLLM 统一管理多模型调用。

#### **二、模块详细设计**

##### **模块 1: WerewolfGameMaster（游戏控制层主类）**

**作用**：整个游戏的“大脑”，维护全局状态，控制回合推进，处理夜晚私有行动和白天公开讨论。继承或扩展 Concordia 的 GameMaster 类。

**关键属性**：

- `players: List[ConcordiaAgent]`
  – 所有玩家 Agent 列表。
- `roles: Dict[str, str]`
  – 玩家名 → 角色（"WEREWOLF", "SEER", "VILLAGER"）。
- `alive_players: Set[str]`
  – 当前存活玩家。
- `phase: str`
  – 当前阶段（"SETUP", "NIGHT", "DAY\_ANNOUNCEMENT", "DAY\_DISCUSSION", "DAY\_VOTING", "GAME\_OVER"）。
- `day_count: int`
  – 当前天数。
- `night_kill_target: str | None`
  – 夜晚狼人击杀目标。
- `seer_check_result: Dict[str, str]`
  – 预言家查验结果（私有写入记忆）。

**关键方法**：

- `setup_game()`
  ：随机分配角色，创建 Agent，注入角色组件和私有 Prompt。
- `run_game_loop()`
  ：主循环，根据 phase 调用对应方法，直到游戏结束。
- `run_night_phase()`
  ：处理夜晚行动（狼人杀、预言家查）。
- `run_day_announcement()`
  ：广播死亡信息，检查胜负。
- `run_day_discussion()`
  ：使用 Concordia Scene 进行多轮公开对话。
- `run_day_voting()`
  ：轮询每个 Agent 获取结构化投票，结算处决。
- `check_victory()`
  ：判定狼人/好人胜利条件。
- `broadcast(message: str)`
  ：向所有存活 Agent 添加公开事件到记忆。
- `private_message(agent_name: str, message: str)`
  ：仅向指定 Agent 添加私有记忆。

##### **模块 2: WerewolfAgent（Concordia Agent 定制）**

**作用**：每个玩家继承 Concordia 的标准 Agent 类，注入狼人杀专用组件。

**关键配置**：

- `model`
  : 通过 LiteLLM 指定的模型名称（根据角色路由）。
- `persona`
  : 社会人设（e.g., "你是一个胆小的大学生，叫小明"），增强角色扮演趣味。
- `components`
  : 列表，包含自定义组件。

##### **模块 3: 自定义 Component**

###### **3.1 RoleIdentityComponent（角色身份组件）**

**作用**：注入并永久存储玩家的真实游戏角色和目标，确保 Agent 行为符合身份。

**方法**：

- `__init__(role: str, teammates: List[str] | None)`
  ：存储角色和队友（狼人知道彼此）。
- `activate()`
  ：在 Agent 初始化时，向 System Prompt 注入："你的底牌是 {role}。你的目标是...（胜负描述）"。

###### **3.2 PrivateMemoryComponent（私有记忆隔离组件）**

**作用**：区分公开记忆和私有记忆，防止信息泄露（如狼人白天不小心说出夜晚讨论）。

**方法**：

- `add_public_memory(event: str)`
  ：添加到 Concordia 的 Associative Memory（所有 Agent 可见的部分）。
- `add_private_memory(agent_name: str, event: str)`
  ：仅添加到指定 Agent 的记忆。
- `get_relevant_memory(query: str, is_private: bool)`
  ：检索时区分公开/私有。

###### **3.3 DeceptiveThoughtComponent（双重思维组件 - 核心难点）**

**作用**：实现“心口不一”，狼人/预言家能伪装发言。

**方法**：

- `generate_thought()`
  ：先强制 LLM 输出
  `[INNER_THOUGHT]`
  标签的内心独白（结合私有记忆和角色目标）。

  - `generate_public_speech(inner_thought: str)`

    ：基于内心独白生成

    `[PUBLIC_SPEECH]`

    标签的公开发言（Prompt 强调：绝不能泄露底牌）。

    - `post_process_output(output: str)`

      ：后处理检查，如果检测到泄密关键词，强制重生成。

  ###### **3.4 NightActionComponent（夜晚行动组件）**

  **作用**：处理夜晚的结构化私有行动（狼人杀、预言家查）。
  **方法**：

  - `activate_if_night()`
    ：仅在夜晚阶段触发。
  - `generate_action()`
    ：Prompt LLM 输出 JSON，例如：

    - 狼人：
      `{"action": "KILL", "target": "Player_X", "reason": "..."}`
    - 预言家：
      `{"action": "CHECK", "target": "Player_Y"}`
  - `validate_action(json_output)`
    ：GM 校验行动合法性。

  ##### **模块 4: ModelRouter（多模型路由层）**

  **作用**：使用 LiteLLM 实现不同角色使用不同模型，模拟“智商差异”。
  **关键方法**：

  - `pick_model_for_role(role: str) -> str`
    ：

    - "WEREWOLF" → "openai/gpt-4o" 或 "anthropic/claude-3-5-sonnet"（强伪装能力）。
    - "SEER" → "openai/gpt-4"（强逻辑推理）。
    - "VILLAGER" → "openai/gpt-3.5-turbo" 或本地 "ollama/llama3:8b"（成本低，偶尔出错更真实）。
  - 在创建 Agent 时传入对应 model\_name。
  - LiteLLM 配置支持 fallback 和负载均衡。

  ##### **模块 5: Logging & Debugging（调试模块）**

  **作用**：便于观察 Agent 行为。
  **方法**：

  - `log_inner_thought(agent_name, thought)`
    ：打印所有 Agent 的内心独白。
  - `log_game_state()`
    ：每阶段结束打印存活、角色（隐藏真实角色，只显示公开信息）。
  - `save_transcript()`
    ：保存完整对话日志。

  #### **三、游戏流程状态机（Phase 详细设计）**

  1. **SETUP** → 分配角色 → 注入私有身份 → 进入 NIGHT。
  2. **NIGHT**：

      - 狼人：GM 单独询问狼人 Agent → 获取 KILL JSON → 记录目标。
      - 预言家：GM 单独询问预言家 → 获取 CHECK JSON → 判定结果 → 写入预言家私有记忆："你查验了 X，他是好人/狼人"。
  3. **DAY_ANNOUNCEMENT**：

      - 结算夜晚死亡 → 广播 "X 被杀了"（若无人死则平安夜）。
      - 检查胜负。
  4. **DAY_DISCUSSION**：

      - 创建 Concordia Scene，只包含存活 Agent。
      - 运行固定轮数（e.g., 每人发言 2-3 轮）。
      - Agent 使用 DeceptiveThoughtComponent 生成发言。
  5. **DAY_VOTING**：

      - GM 轮询每个存活 Agent：Prompt "请投票，输出 JSON: {'target': 'Player\_Y', 'reason': '...'}".
      - 统计票数 → 处决最高票者（平票随机或无人死）。
  6. **GAME_OVER**：宣布胜方。

  #### **四、开发路线图与风险点**

  1. **阶段 1**：实现 GameMaster + 基本 Agent（无 Component），跑通“广播消息 → Agent 回应”闭环。
  2. **阶段 2**：加入 RoleIdentity 和 NightAction，跑通夜晚私有行动。
  3. **阶段 3**：加入 DeceptiveThought，实现白天伪装讨论。
  4. **阶段 4**：接入 LiteLLM 多模型 + 完整胜负判定。
